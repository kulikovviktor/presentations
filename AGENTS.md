# Правила публикации презентаций

Этот файл читают агенты (Codex, Claude Code, Gemini CLI, Cursor, Copilot и другие) и люди. `CLAUDE.md` и `GEMINI.md` в корне только ссылаются сюда. Если инструкции пользователя расходятся с этим файлом, спроси пользователя; без явного указания правила ниже обязательны.

## Структура репозитория

```
presentations/
├── README.md            индекс всех презентаций, обновляется при каждом добавлении
├── AGENTS.md            этот файл
├── CLAUDE.md            указатель на AGENTS.md
├── GEMINI.md            указатель на AGENTS.md
├── _template/           шаблон папки презентации
│   └── README.md
└── <slug>/              одна презентация = одна папка в корне
    ├── index.html       сама презентация, один самодостаточный файл
    ├── README.md        паспорт презентации (см. раздел ниже)
    └── assets/          необязательно: картинки, шрифты, данные
```

## Как добавить презентацию

1. Придумай slug: латиница в нижнем регистре, слова через дефис, 2–4 слова, описывает тему, без дат и версий. Примеры: `office-model-deck`, `q3-sales-review`, `onboarding-support-team`. Убедись, что папки с таким именем ещё нет.
2. Скопируй `_template/` в `<slug>/`.
3. Положи презентацию в `<slug>/index.html`. Требования к файлу ниже.
4. Заполни `<slug>/README.md` по шаблону. Все поля обязательны.
5. Добавь строку в таблицу в корневом `README.md`. Строки отсортированы по дате, новые сверху.
6. Пройди чеклист в конце этого файла.
7. Сделай коммит: `feat(<slug>): add presentation v1.0.0`.

## Требования к index.html

- Открывается двойным кликом из файловой системы: один файл, без сборки, без сервера, без `package.json`.
- CSS и JavaScript лежат внутри файла.
- Внешние ресурсы разрешены только двух видов: шрифты с Google Fonts (с запасным системным стеком в `font-family`) и библиотеки с cdnjs.cloudflare.com, cdn.jsdelivr.net или unpkg.com с закреплённой точной версией в URL. Без интернета презентация должна оставаться читаемой.
- Картинки кладутся в `assets/` и подключаются относительным путём, либо встраиваются как data URI. Общий размер папки презентации не больше 10 МБ.
- Работает при ширине экрана 400 px (телефон) и на десктопе. Горизонтальной прокрутки страницы быть не должно; широкие таблицы и схемы прокручиваются внутри своего контейнера.
- Поддерживает светлую и тёмную тему через `prefers-color-scheme`, либо использует одну тему с явно заданным цветом фона и текста.
- Есть навигация: прокрутка или стрелки клавиатуры, виден номер текущего слайда и их общее количество.
- В `<head>` стоит комментарий-паспорт с теми же данными, что в README: название, кем собрано (агент или продукт и идентификатор модели), дата, версия.
- `<html lang="…">` указывает язык презентации. Язык по умолчанию русский, если заказчик не просил другой.
- Схемы и диаграммы предпочтительно рисовать как inline SVG с цветами из CSS-переменных, чтобы они переключались вместе с темой.
- В файле нет токенов, ключей, внутренних ссылок компании и персональных данных третьих лиц.

## Требования к README.md презентации

Шаблон лежит в `_template/README.md`. Обязательные поля:

| Поле | Что писать |
|---|---|
| Название | Заголовок первого уровня, совпадает с `<title>` в index.html |
| Описание | 2–4 предложения: о чём презентация и из чего состоит |
| Аудитория | Для кого сделано и какой уровень подготовки предполагается |
| Заказчик | Кто попросил собрать (имя, логин GitHub) |
| Собрано | Агент или продукт и точный идентификатор модели, например `Claude Fable 5.1 (claude-fable-5-1)`, `Codex (gpt-5-codex)`, `Gemini CLI (gemini-2.5-pro)` |
| Дата | Дата первой публикации, формат `ГГГГ-ММ-ДД` |
| Версия | Текущая версия по semver, совпадает с верхней записью changelog |
| Как открыть | Как запустить и как листать |
| Источники | Ссылки на материалы, из которых взяты факты и цифры; если фактов нет, так и написать |
| Changelog | Все версии, новые сверху, формат ниже |

## Версии и changelog

- Нумерация по semver `MAJOR.MINOR.PATCH`:
  - MAJOR: переработана структура или смысл презентации, старая версия уже не взаимозаменяема с новой.
  - MINOR: добавлены или удалены слайды, схемы, разделы.
  - PATCH: правки текста, опечаток, стилей, цифр без изменения состава слайдов.
- Запись changelog:

```
### 1.1.0 — 2026-10-20 — Codex (gpt-5-codex)

- Добавлен слайд про стоимость запроса.
- Исправлена опечатка на слайде 4.
```

- При каждом обновлении: подними версию, добавь запись в changelog, обнови паспорт в `<head>` index.html, поле Версия в README и строку в корневом README.
- Если обновляешь чужую презентацию, в записи changelog укажи себя, прежние записи не трогай.

## Коммиты

- `feat(<slug>): …` для MINOR и MAJOR изменений и для новой презентации.
- `fix(<slug>): …` для PATCH.
- `docs(<slug>): …` для правок только в README.
- `docs(repo): …` для правок корневого README или этого файла.
- Один коммит содержит изменения одной презентации. Корневой README можно менять в том же коммите.

## Чего не делать

- Не менять другие папки, кроме той, над которой работаешь, без явной просьбы.
- Не менять этот файл без явной просьбы пользователя.
- Не переименовывать и не удалять опубликованные папки: на них могут быть ссылки.
- Не добавлять сборщики, зависимости, `node_modules`, CI-конфиги.
- Не класть в репозиторий исходники в форматах PowerPoint, Keynote, Google Slides. Если такой файл нужен, экспортируй в HTML или положи PDF в `assets/` рядом с index.html.

## Чеклист перед коммитом

- [ ] Папка `<slug>/` содержит `index.html` и `README.md`.
- [ ] `index.html` открывается локально, проверен при ширине 400 px и на десктопе, горизонтальной прокрутки страницы нет.
- [ ] Светлая и тёмная тема выглядят читаемо.
- [ ] Паспорт в `<head>` совпадает с README: название, агент и модель, дата, версия.
- [ ] Все обязательные поля README заполнены, changelog начинается с текущей версии.
- [ ] Строка добавлена или обновлена в таблице корневого `README.md`.
- [ ] В файлах нет секретов, внутренних ссылок и персональных данных третьих лиц.
- [ ] Сообщение коммита соответствует формату.
